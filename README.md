# 엑셀 모아보기 (시제품)

같은 구조(첫 줄 제목이 같은)의 엑셀·CSV 파일과 탭 여러 개를 끌어다 놓으면, 하나로 모아 바로 검색·필터하는 화면.
서버 없이 브라우저 안에서만 동작하고, 파일은 PC 밖으로 나가지 않는다.

- `index.html` 하나로 완결. 라이브러리는 `vendor/` 로컬 번들(sql.js, SheetJS) — 인터넷 없이, 파일 더블클릭(file://)으로도 열리게.
- 무거운 일(엑셀 읽기·합치기·조회)은 Web Worker 안의 메모리 SQLite에서 한다.
- **2026-11-06 다시 짬**: 처음 범용판은 새로 짜면서 칸 필터가 "포함" 하나뿐이었다. projectA(`admin/data-converter.html`) 조회 부분을 가져와 범용으로 다듬었다 —
  표 구조(엑셀 제목 = SQLite 칸 이름), 칸 제목 옆 ▾ **필터 패널(값·조건·범위·배경색·글자색, 칸끼리·축끼리 AND)**, 걸린 조건 **칩**(하나씩 ×),
  **칸 너비 끌기**, 줄 누르면 **상세보기**(출처 파일 › 탭 · 엑셀 행 번호 + 복사), **제목 맞추기**, 날짜 칸 판별(엑셀 날짜 서식 → YYYY-MM-DD, 하루 빠른 문제 없는 방식),
  숫자 칸 쉼표·오른쪽 정렬·숫자 정렬, 스크롤 연동 윈도잉. 한 회사 전용(고정 칸 이름, 특정 칸 기준 나누기, 월 탭 규칙, 따로 있던 권한 설정 화면, 빈칸 기본값, 처음엔 빈 목록)은 뺐다.
- 숨은 칸: 출처(`\u0001파일`/`\u0001탭`/`\u0001행`), 검색용 글자(`\u0001all`), 색(`칸 이름\u0001배경`/`\u0001글자`) — 엑셀 제목에 들어갈 수 없는 글자를 붙여 사용자 칸과 안 겹침.

## 합치는 규칙 (2026-11-06)

- 탭마다 위 50줄 안의 첫 번째 비어 있지 않은 줄 = 제목 줄. 끝쪽 빈 제목은 버리고, 가운데 빈 제목·같은 제목은 "(빈 제목 3)"·"이름 (2)"로 구분.
- **기준 제목** = 이미 모아 둔 데이터의 제목, 없으면 넣는 탭들 중 가장 많은 탭이 쓰는 제목 구성.
- 기준 제목과 겹치는 게 **절반 미만**인 탭(메모·요약 탭)은 빼고 요약에 알림. 빈 탭도 빼고 알림.
- 절반 이상이면 합친다. 칸 순서는 이름으로 맞춤. 기준에 없는 제목은 넣기 전 **확인창**에서 "○○로 맞추기 / 새 칸으로 추가 / 읽지 않기"를 고른다.
  비슷한 제목(띄어쓰기·괄호만 다르거나 한두 글자 오타)은 미리 골라 두고 확인을 받는다. 고른 것은 이 브라우저(`emv_header_map_v1`)에 기억 → 다음엔 묻지 않고 그대로.
  고를 게 없으면 확인창 없이 바로 합친다. 기준 제목이 없는 탭은 그 칸이 빈칸.
- 같은 이름의 파일을 다시 넣으면 그 파일 몫을 통째로 교체. 요약의 "넣은 파일"에서 [빼기].
- 완전히 빈 줄은 넣지 않는다. 엑셀은 한 번만 다 읽어 두고(미리보기) 합칠 때 그대로 쓴다.
- [가짜 데이터로 체험]: 쇼핑몰 주문 가짜 데이터(탭 하나에 5년치 파일 + 월별 탭 60개 파일)를 실제 xlsx로 만들어 같은 과정으로 읽는다.

**디자인(2026-11-09~)**: 에디토리얼 — "사건 기록"(가르시아가 "디자인 톤 28가지" 중 고름). 종이색 바탕, 명조 제목, CASE 번호, 빨간 "손해" 도장, 찾은 줄은 오려 붙인 쪽지. 엑셀은 짙은 초록(#1D6B3F) 포인트로만 — 장면이 주인공. 앱도 같은 색(종이 바탕 + 초록, 파란색에서 바꿈).

## 셀 색깔 (2026-10-29)

- xlsx·xlsm에서 직접 칠한 **배경색·글자색**을 읽어 표에 원본처럼 칠하고, 칸 제목 옆 ▾ 필터 패널의 **배경색·글자색 탭**에서 그 칸에 실제로 쓰인 색(+색 없음)을 체크해 거른다(2026-11-06부터 — 예전엔 [색] 버튼).
- 직접 지정한 색(rgb), 팔레트의 테마색(밝게/어둡게 포함), 옛 색 번호(indexed)를 모두 실제 색으로 바꿔 읽는다. 흰색 채우기·검정 글자는 색 없음으로 본다.
- 제목 줄 색, 값 없이 칠만 남은 칸은 뺀다.
- 못 읽는 것은 요약의 "색 정보 안내"로 알린다: 조건부 서식으로 칠해진 색, 옛 형식(.xls). CSV는 원래 색이 없다.
- 체험용 가짜 데이터에도 색이 있다(배송상태 취소 = 빨간 칸, 반품 = 노란 칸, 금액 50만 원 이상 = 파란 글자).
- 읽는 시간: 같은 컴퓨터(클라우드 개발 환경, 위 표보다 느린 PC)에서 가짜 데이터 50만 건 24.1초 → 27.7초(색칠된 칸 약 18만 개 포함). 색 있는 서식이 없는 파일은 탭을 훑지 않아 거의 그대로.
- 테스트용 색 엑셀: `tests/fixtures/색.xlsx`(`python3 tests/make-color-fixture.py`로 다시 만듦).

## 빠르게 다시 열기 (2026-10-29)

모은 데이터(SQLite DB)를 통째로 저장해, 다음엔 엑셀을 다시 읽지 않고 바로 연다. 위 [저장] 버튼.

- **파일로 저장**: `.db` 파일 하나로 내려받기. 다음엔 그 파일을 끌어다 놓으면 열림(엑셀과 같이 넣으면 저장본을 먼저 열고 엑셀을 더함). 다른 PC로 옮길 수 있음.
  - **비밀번호 걸기(선택)**: 브라우저 내장 WebCrypto(AES-GCM 256, PBKDF2 20만 번)로 파일 전체를 암호화. 틀리면 다시 묻고, 파일이 잘렸으면 "손상"으로 따로 알림. 잊으면 아무도 못 엶.
- **이 브라우저에 저장**: IndexedDB에 하나만. 다음에 열면 처음 화면에 [이어서 보기]·[지우기].
- 넣은 파일 요약(뺀 탭 포함)과 색 정보도 같이 저장되어 그대로 돌아온다.
- 실측(가짜 데이터 50만 건 11칸, 파일 2개·탭 61개, 클라우드 개발 환경): 엑셀 다시 읽기 28.9초 → 저장본 열기 **0.49초**, 브라우저 저장 0.38초, 비밀번호 파일 1.9초. 파일 크기 163MB, 저장 0.3초(비밀번호 1.7초).
- 웹 체험 페이지(claude.ai)에서는 내려받기가 막혀 있어 "파일로 저장"이 동작하지 않는다. "브라우저에 저장"은 동작.

## 직원별 권한 — 직원용 파일 (2026-10-29)

서버가 없으므로 화면에서 숨기는 방식은 쓰지 않는다(파일을 다른 도구로 열면 다 보임). 대신 **직원마다 볼 수 있는 줄·칸만 담은 저장본(.db)을 따로 만든다.** 위 [직원용 파일] 버튼.

- **줄을 나눌 칸**(예: 담당자)을 고르고, 직원마다 그 칸의 어떤 값을 볼지 체크(값 찾기·모두·없음). 나누지 않으면 모든 줄.
- **볼 수 있는 칸**을 직원마다 체크. 뺀 칸은 파일에 아예 없고, 전체 검색용 글자도 남긴 칸만으로 다시 만든다. 남긴 칸의 색 정보는 그대로.
- **비밀번호**는 직원마다(선택). 저장본과 같은 암호화.
- 항상 **새 DB에 필요한 줄·칸만 옮겨 담는다**(원본에서 지워서 만들면 지운 내용이 파일 빈 공간에 남을 수 있어서). 넣은 파일 요약도 그 파일 내용 기준으로 새로 만듦(뺀 탭·칸 이름 같은 원본 정보 없음).
- [이 직원 파일 내려받기] 또는 [모두 한 번에 내려받기(zip)]. zip은 압축 없이 직접 만든다(SheetJS의 zip은 한글 파일 이름이 깨짐 → UTF-8 표시를 붙임).
- 직원이 파일을 열면 요약에 "직원용 파일 OOO — 줄 N건 · 칸 N개만" 표시, [직원용 파일] 버튼은 숨김.
- 설정(직원 이름·고른 값·칸·비밀번호)은 이 브라우저 localStorage(`emv_staff_v1`)에 칸 **이름**으로 기억 → 다음 달 새 엑셀에도 같은 설정. ⚠️ 직원 비밀번호도 여기 글자 그대로 들어가므로 관리자 PC에서만 쓸 것.
- 막을 수 없는 것: 볼 수 있게 한 내용을 직원이 캡처·복사해 옮기는 것.
- 검증: 비밀번호 없는 직원 파일을 바이트 그대로 뒤져 다른 직원 이름·뺀 칸 값이 없음을 확인(테스트에 포함). 실측(가짜 50만 건): 직원 1명(10만 건) 3.5초 · 32MB, 직원 5명 zip 15.7초 · 163MB.

## 폴더 찾아보기 (2026-11-09 시제품)

첫 화면의 두 번째 입구. 폴더를 한 번 연결해 두면 그 안의 엑셀·CSV를 **탭마다 원래 제목 그대로** 읽어 두고, 키워드로 그 줄을 **최신순**으로 찾는다.
제목을 맞추거나 탭을 빼지 않는다(모아보기와 다른 점). 기능 정의·기본값은 [docs/폴더찾아보기_기능정의.md](docs/폴더찾아보기_기능정의.md).

- 읽기(2026-11-09 개정): 위쪽 30줄 중 ① 가장 많이 찬 줄의 절반 이상(최소 2칸)이 찼고 ② 그 아래 줄들(값 있는 줄 10개)의 값이 이 줄이 차지한 칸 안에 80% 이상 들어오는 첫 줄을 제목 줄로 본다 — 맨 위 한 칸 제목, 칸 몇 개에 걸친 안내 글("거래처: … · 기간: …")은 건너뜀. 빈 줄만 빼고 합계·메모 줄도 그대로.
- **제목 줄 위의 줄도 저장**: 거래명세서처럼 업체명이 표 위 안내 글에만 있는 양식도 찾기에 걸리게, 줄마다 칸 글자를 " · "로 이어 "표 위쪽 안내 글"로 따로 둔다(날짜는 그 표의 가장 최근 날짜). 같은 줄 AND라 "안내 글의 업체명 + 표 안의 품목"을 한 번에 찾지는 못함. **건수에는 넣지 않는다** — 위쪽 "줄 N개"·찾기의 "일치 N줄"은 표 데이터 줄만 세고, 안내 글은 "표 위 안내 글 M줄"로 따로 보여 줌.
- 날짜: 탭마다 날짜 칸 하나를 고른다(칸 이름 일자·날짜·출고일… + 값 모양 2026-11-02 / 2026.11.02 / 20261102 / 엑셀 날짜 서식). 없으면 파일 수정일로 정렬하고 "날짜 칸 없음"을 붙인다.
- 찾기(2026-11-09 개정, 사용자 결정): **찾을 말 전체를 띄어 쓴 그대로 한 덩어리로**(부분 일치) — "테스트 상사"는 "테스트 상사"가 들어간 줄만. 여러 말이 모두 들어간 줄은 `+`로 이어 씀(`테스트상사+P0123`). 두 입구 같음. 폴더 찾아보기는 대소문자·숫자 쉼표·회사 표기((주)·㈜·주식회사·(유)·유한회사) 차이는 무시하고, 띄어쓰기 무시는 설정에서 켤 수 있음(기본 끔, 두 칸 띄운 것은 한 칸으로 봄). 설정을 바꾸면 엑셀을 다시 읽지 않고 찾기용 글자만 다시 만든다.
- 결과: 요약(줄 수·파일 수·가장 최근/오래된 날짜), 기간 단추(전체·7일·30일·90일·1년, 기간 밖에 몇 줄 더 있는지), 같은 탭끼리 묶어 그 탭 제목으로 표시, 찾은 칸 노란색, 300줄씩 그림, 상한(기본 1만 줄) 넘으면 안내. 줄을 누르면 출처(폴더/경로 › 탭 · 엑셀 행)와 [위치 복사].
- 다시 확인: 경로·크기·수정 시각을 비교해 새 파일·고친 파일만 다시 읽고 없어진 파일은 뺀다. 최근에 고친 파일부터 읽어, 처음 연결 중에도 최근 것부터 찾을 수 있다. 열 때·[다시 확인]·변경 감지(FileSystemObserver, 없으면 창으로 돌아올 때).
- 못 읽은 파일(암호·깨짐·상한보다 큼·다른 프로그램이 쓰는 중)은 목록으로 알린다. `.xlsx`인데 엑셀 압축 파일이 아니면 깨진 파일로 본다(SheetJS는 아무 글자나 표로 읽어 버려서). `.xls`는 HTML로 된 가짜 xls가 흔해서 그대로 읽어 본다.
- **읽은 파일 보기**(2026-11-10): 위쪽 "파일 N개 ▾"를 누르면 폴더별 목록 — 파일마다 줄 수·수정일, 못 읽은 파일은 이유와 함께, "확인할 것" 표시. 파일 이름을 누르면 그 파일의 탭 이름·줄 수·칸 제목(앞 12칸), 제목 줄 위 안내 글. 처음엔 작은 폴더(10개 이하)만 펼침. 탭 정보는 펼칠 때 작업 스레드에서 가져옴(`fsSheets`).
- 저장본: 기본은 **브라우저 안**. http(s)로 열면 OPFS 파일, **파일 더블클릭(file://)으로 열면 크롬이 OPFS를 막아서 IndexedDB**에 넣는다(2026-11-09 확인). 저장 전 여유 공간 확인, 영구 보관 요청, 실패하면 화면에 알림. 설정에서 내가 고른 폴더(`엑셀모아보기_찾아보기.db`)로 바꿀 수 있다. 설정에 크기·[저장본 지우기].
- 크롬·엣지만(폴더 고르기 기능). claude.ai 웹 체험 페이지(iframe)에서는 폴더 고르기가 막힐 가능성이 커서 아직 안 올림.

실측(2026-11-09, 개발 환경 헤드리스 크롬, http, 가짜 데이터 — 하루 1파일 × 365일, 파일마다 1,000줄, 제목 구성 3가지(5~7칸)가 섞임, 맨 위 한 칸 제목 줄, 합계 87.5MB):

| | 시간 |
|---|---|
| 처음 읽기(36만 5천 줄) | 11.9초 — 최근 30일치는 1.3초 만에 찾기 가능 |
| 찾기(업체명·상품코드·송장번호) | 0.2~0.4초 |
| 다시 확인(바뀐 것 없음) | 0.20초 |
| 다시 열기(저장본 55MB 불러오기 + 바뀐 파일 확인) | 0.33초 |

다시 확인: `LANG=C.UTF-8 node tests/folder-search.test.js` — 헤드리스 크롬은 폴더 고르기 창을 못 띄워서 OPFS 안에 만든 가짜 폴더(http) / 메모리 흉내 폴더(file://)를 넘긴다.
테스트는 보통 프로필로 띄운다(시크릿 프로필에서는 OPFS 폴더 핸들을 IndexedDB에 넣고 새로 고치면 크롬이 페이지를 닫음). 한글 파일 이름 때문에 UTF-8 로케일 필요.
실제 폴더 고르기, "방문할 때마다 허용"으로 다시 묻지 않기, 파일 더블클릭 화면에서 폴더 기억은 Windows 크롬에서 아직 확인 못 함.

## 엑셀 점검 (2026-11-09)

엑셀에 있는 그대로는 표에 보여 줄 수 없는 칸을 **빼지 않고 고쳐 넣은 뒤, 무엇을 고쳤는지 알린다** (두 입구 모두).
projectA "엑셀 점검"(`scripts/merge-split.real-data-check.html`)을 가져와 다듬음 — 거기서 실제 엑셀로 해 보니 병합은 칸을 넓혀 놓은 것인 경우가 많아, 정상/오류 판단은 사람에게 맡긴다.

| 엑셀에 있는 것 | 전에는 | 이제 |
|---|---|---|
| 수식 오류값(#N/A·#REF!·#DIV/0! 등) | 빈 칸이 됨(SheetJS가 빈 글자로 줌), 알림 없음 | `#N/A`처럼 글자로 넣고 흐리게 표시 |
| 병합된 칸(제목 줄 아래) | 첫 칸에만 값 | 몇 곳인지 알림. "병합된 칸 채우기"(첫 화면·폴더 설정 공용, 기본 끔)를 켜면 같은 값으로 채움 |
| 안 보이는 글자(폭 없는 공백·BOM·제어 문자) | 그대로 → 찾기에 안 걸림 | 값은 그대로, 찾기용 글자에서만 늘 지움 |

요약(모아보기)·"확인할 것"(폴더 찾아보기)에 탭마다 개수와 위치(행·칸, 탭마다 30곳까지)만 보여 준다 — 칸 값은 띄우지 않음.
30만 건 가짜 데이터 읽기 시간은 전과 같음(12.5~13.2초, 2026-11-09). 확인: `LANG=C.UTF-8 node tests/excel-check.test.js`.
