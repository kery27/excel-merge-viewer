# 폴더 찾아보기 — 기능 정의 (초안 2판 · 2026-11-09)

> 시제품을 만들기 전에 정리한 기능 정의. **확정 아님** — "확인 필요"로 표시한 것은 친구(물류센터 운영) 대화나 실측으로 정한다.
> 2판(같은 날): 쓰임새 세 가지와 빈도를 반영, 저장 위치 결정(브라우저 기본 + 직접 지정), 나머지는 기본값을 정하고 설정에서 바꿀 수 있게 함.

## 1. 왜 만드나 — 실제로 들은 사례

물류센터를 운영하는 가르시아의 친구(2026-11-08, 가르시아가 전해 들음):

- **반품이 들어오면, 그 물건이 언제 나갔는지** 확인하려고 **최근 30일치 발주(출고) 이력 엑셀을 하나하나 뒤진다.**
- **업체(거래처) 정보 이력**도 같은 식으로 찾는다.
- 지금 방식: 원하는 키워드가 있으면, 정해 둔 폴더 범위 안에서 그 키워드가 든 파일을 찾고, 파일을 열어 일부를 확인한다.

여기서 나온 문제:

| 문제 | 지금 모아보기로는 |
|---|---|
| 엑셀이 날짜별·업체별로 흩어져 있다 | 파일을 골라 넣어야 함 |
| 파일마다 제목 줄(칸 구성)이 제각각이다 | 제목이 많이 다르면 빼 버림 |
| 쓰레기 줄·합계 줄·메모 탭이 섞여 있다 | 맞추라고 묻거나 빼 버림 |
| 키워드 하나로 **그 줄**을 바로 보고 싶다 | 합친 뒤에야 검색 가능 |

→ **데이터 정리를 강요하지 않고**, 폴더째 연결해 두면 키워드로 바로 그 줄을 보여 주는 기능이 필요하다.

## 2. 한 줄 정의

**"폴더를 한 번 연결해 두면, 키워드 하나로 그 안의 모든 엑셀에서 해당 줄을 찾아 최신순으로 보여 준다. 제목 형식을 맞출 필요가 없다."**

지금의 "모아보기"(같은 구조끼리 합쳐 칸 조건으로 거르기)와 나란히 두는 두 번째 입구다. 찾은 뒤 같은 구조끼리는 모아보기로 넘긴다.

## 3. 쓰임새 세 가지 — 빈도가 다르다

| 쓰임새 | 누가 | 찾는 기간 | 빈도 | 설계에 주는 뜻 |
|---|---|---|---|---|
| **A. 업체 이력 조회** | 영업 | 전체(몇 년) | **자주** — 하루에도 여러 번 | 같은 업체를 반복해서 찾음 → 검색이 늘 빨라야 함, 업체명 표기 차이((주)·띄어쓰기) 흡수, 결과 맨 위에 "처음·마지막 거래일·건수" 요약 |
| **B. 반품 물건 출고 확인** | 물류(친구) | **최근**(대개 30일 안) | 반품 들어올 때마다 | 최근 것이 맨 위(최신순), 최근 파일부터 읽어 준비 전에도 찾을 수 있게 |
| **C. 오래된 기록 확인** | 가르시아 고객 사례 | **몇 년 전** | **드묾** — 가끔 | 드물지만 **빠짐없이** 나와야 함 → 옛 파일도 전부 읽어 둠. 대신 처음 읽기가 조금 오래 걸려도 괜찮음 |

결론: **기본은 "전체 기간 · 최신순"**. 자주 쓰는 A·B는 빨라야 하고, 드문 C는 느려도 되지만 빠지면 안 된다.

## 4. 쓰는 장면

**처음 한 번**
1. [폴더 연결] → 엑셀이 쌓이는 폴더를 고른다.
2. **최근에 고친 파일부터** 읽는다(진행률 표시). 최근 파일을 다 읽으면 바로 찾을 수 있고, 옛 파일은 계속 읽는 중이라고 표시한다("2023년 이전 파일 읽는 중 — 그 기간은 아직 결과가 덜 나올 수 있어요").
3. 끝나면 "파일 312개 · 줄 48만 개 준비됨".

**그다음부터**
1. 화면을 연다 → 저장해 둔 것을 불러오고, 바뀐 파일만 다시 읽는다(몇 초). 새로 생긴·고친·지운 파일 개수를 알려 준다.
2. 검색창에 업체명·상품코드·송장번호 같은 키워드를 넣는다.
3. 결과 맨 위 요약: "일치 7줄 · 파일 3개 · 가장 최근 2026-11-02 · 가장 오래된 2021-03-05".
4. 결과는 **최신순**. 기간 빠른 단추(전체·7일·30일·90일·1년)로 좁힌다.
5. 줄을 누르면 그 줄 전체 + 출처(파일 경로 › 탭 · 엑셀 몇 행)와 [위치 복사].
6. 필요하면 [이 결과 모아보기]로 같은 구조 탭끼리 합쳐 칸 조건으로 더 거른다.

## 6. 미리 읽은 내용(저장본)을 둘 곳 — 정함

**기본: 브라우저 안(크롬이 정한 곳). 설정에서 내가 고른 폴더로 바꿀 수 있다.** (2026-11-09 가르시아 결정)

| | 브라우저 안 (기본) | 내가 고른 폴더 (선택) |
|---|---|---|
| 위치 | 크롬이 관리하는 이 사이트 전용 저장 공간(브라우저 파일 시스템). 사용자에게는 보이지 않음 | 원하는 폴더에 `엑셀모아보기_찾아보기.db` 파일로 |
| 장점 | 폴더 쓰기 허용이 필요 없음, 설정 없이 바로 | 눈에 보이고 백업·이동 가능, 공유 폴더면 여러 명이 같이(N5) |
| 주의 | 이 PC·이 브라우저에만 남음. 크롬 방문 기록·사이트 데이터를 지우면 같이 지워짐(원본 엑셀이 있으니 다시 읽으면 됨) | 그 폴더 쓰기 허용 필요 |

- 예전에 "브라우저 자동 저장"을 기각한 이유 두 가지를 이렇게 다룬다.
  - **대용량에서 조용히 실패한 전례**: 그때는 IndexedDB에 통째로 넣었다. 이번엔 큰 파일용 브라우저 파일 시스템에 저장하고, 저장할 때마다 **용량 여유를 먼저 확인**하고, 실패하면 **화면에 알린다**(조용히 넘어가지 않음). 크롬에 "지우지 말아 달라(영구 보관)" 요청도 한다.
  - **고객 데이터 사본이 브라우저에 남는 것**: 설정 화면에 "이 PC 브라우저에 사본이 저장됩니다"를 적고, 크기와 [저장본 지우기]를 늘 보여 준다. 걱정되면 폴더 지정으로 바꾸게 안내.

## 8. 제약·전제 (지금 확인된 것)

- **크롬·엣지만.** 파이어폭스·사파리는 폴더 고르기 기능이 없다.
- 이 개발 환경의 크롬(153)에서 파일 더블클릭(file://)으로 연 화면에도 폴더 고르기·변경 감지·브라우저 파일 시스템 기능이 있음을 확인함.
- "다음에 열 때 폴더를 다시 묻지 않기"는 크롬의 **"방문할 때마다 허용"**이 필요하다. 파일 더블클릭 화면에서도 되는지는 **확인 필요** — 안 되면 웹 주소(홈페이지 체험판 등)로 열거나, 열 때 [폴더 다시 허용] 한 번 누르기.
- 브라우저 저장 공간은 **사이트 주소마다 따로**다. 파일 더블클릭으로 연 것과 홈페이지 주소로 연 것은 서로 다른 저장본을 쓴다.
- "브라우저를 켜자마자"가 아니라 **"이 화면을 열면"** 시작된다.
- 처음 전체 읽기 시간은 파일 수·크기에 따라 분 단위가 될 수 있다(**실측 필요**). 최근 파일부터 읽으므로 최근 것은 먼저 찾을 수 있다.
- 옛 형식(.xls)은 색을 못 읽는다. 암호 걸린 엑셀은 못 읽는다.

## 9. 데이터·보안

- 데이터는 PC 밖으로 나가지 않는다(지금 원칙 그대로).
- 브라우저 저장본은 이 PC 브라우저에 남는다 — 설정에 크기와 [저장본 지우기]를 늘 보여 준다.
- 폴더 저장본은 그 폴더의 권한을 따른다. 비밀번호를 거는 선택지는 지금 저장 기능 재사용.
- 테스트는 가짜 데이터로만. 친구의 실제 파일은 받지 않고, 친구 PC에서 직접 써 보게 한다.

## 10. 잘 됐다고 볼 기준

- **A 업체 이력**: 준비된 뒤 업체명 검색이 **1초 안**, 표기가 달라도((주)·띄어쓰기) 빠짐없이.
- **B 반품 확인**: 화면을 열고 상품코드·송장 하나로 출고 줄을 찾기까지 **10초 안**(바뀐 파일 다시 읽기 포함). 처음 연결 중이라도 최근 30일치는 먼저 찾을 수 있게.
- **C 옛 기록**: 몇 년 전 줄도 **빠지는 것 0**. 형식이 다른 파일이 섞여 있어도 키워드가 든 줄은 전부 나온다.
- 친구가 "지금보다 낫다"며 계속 쓰는지.

## 11. 친구에게 확인할 것

1. 폴더는 어떻게 쌓이나 — 날짜별 파일? 업체별? 한 파일에 날짜별 탭? 하루에 몇 개 생기나?
2. 파일 수·용량은 — 30일치면 몇 개, 1년치면 몇 개?
3. 무엇으로 찾나 — 상품코드? 송장번호? 주문번호? 업체명? 여러 개를 같이?
4. 반품 정보는 어떻게 오나 — 한 건씩? 반품 목록 엑셀로 여러 건? (→ N1 일괄 찾기)
5. 찾아서 알고 싶은 것 — 출고일만? 업체·수량·담당자까지? 찾은 다음에 무엇을 하나?
6. 업체 이력은 누가, 하루에 몇 번 찾나? 무엇을 보려고(마지막 거래일, 품목, 금액)?
7. 공유 폴더(NAS)인가, 몇 명이 찾나?
8. 지금 한 번 찾는 데 얼마나 걸리나?
9. 지금 쓰는 도구는(윈도우 검색, 엑셀 찾기, 다른 프로그램)? 그걸로 부족한 점은?
10. 이게 되면 돈을 낼 만한가 — 얼마 정도면 사겠나?

## 12. 구현 메모 (시제품 기준)

- 지금 `index.html` 안에 [파일 모아보기]와 [폴더 찾아보기] 두 입구. 엑셀 읽기·날짜 판별·색 읽기·암호화는 그대로 재사용.
- 저장 형식은 모아보기와 다르다: 탭마다 자기 제목을 따로 저장.
  - `files`(경로, 크기, 수정 시각, 상태), `sheets`(파일, 탭, 제목 목록, 날짜 칸), `rows`(탭, 엑셀 행, 칸 값 목록, 검색용 글자, 날짜 값)
  - 검색용 글자는 설정의 "무시" 규칙(띄어쓰기·대소문자·쉼표·회사 표기)을 적용한 글자로 만든다. 설정을 바꾸면 다시 만든다(원본 값은 그대로라 엑셀을 다시 읽을 필요는 없음).
- 날짜 칸 찾기: 칸 이름(일자·날짜·출고일·발주일 등)과 값 모양(YYYY-MM-DD 비율)으로 탭마다 하나 고름. 못 찾으면 파일 수정 시각을 대신 쓰고 "날짜 칸 없음"으로 표시.
- 브라우저 저장: 브라우저 파일 시스템(OPFS)에 SQLite 파일. 저장 전 `navigator.storage.estimate()`로 여유 확인, `navigator.storage.persist()` 요청. 실패는 화면에 알림.
- 폴더 저장: 고른 폴더에 쓰기 허용을 받아 `.db` 파일로.
